# v30.0 Haltech-style rotational idle governor

This test version changes only normal rotational-idle governing behaviour; all v29.7 features and the v29.7 no-LTO build workaround are retained.

## Verified design basis
Haltech documents Rotational Idle as holding a configured Idle Valve Position, progressively cutting more cylinders as RPM approaches End RPM, and cutting all cylinders above End RPM. Activating Engine Demand/TPS is an enable condition; End RPM is not an on/off activation ceiling.

## v30.0 behaviour
- RI enable: existing CLT/switch mode + Maximum TPS + engine running.
- PWM idle valve: fixed at configured `rotationalIdleIAC` for the whole time RI is active.
- Existing `rotationalIdleMaxRPM` is now the **End RPM / rotational-idle target**.
- Progressive cylinder cuts occur over the final **200 RPM below End RPM**.
- At or above End RPM, all ignition outputs are cut; if Fuel + spark is selected, all fuel outputs are also cut.
- Below End RPM - 200, no RI cut is applied.
- The legacy fixed `rotationalIdleCutPercent` byte is retained for EEPROM compatibility but is no longer used by normal RI.
- Independent overheat rotational-idle protection is unchanged and still uses its configured fixed cut percentage.

### Example: 4 sequential ignition outputs, End RPM 1200
- <=1049 RPM: 0 cylinders cut
- 1050-1099 RPM: 1 cylinder cut
- 1100-1149 RPM: 2 cylinders cut
- 1150-1199 RPM: 3 cylinders cut
- >=1200 RPM: all cylinders cut

This first test version deliberately uses a fixed 200 RPM ramp to avoid allocating/migrating another EEPROM setting. If logs show the ramp needs tuning, it can be exposed as a setting later.
