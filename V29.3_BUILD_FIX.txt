Speeduino custom v29.3 - Windows path quoting fix

Functional ECU behaviour is unchanged from v29/v29.2.

The v29.2 log showed that avr-libstdcpp was present and cached locally, but the
compiler still reported standard headers such as <algorithm> and <type_traits>
as missing.

The project path contained a space:
C:\Users\leema\Speeduino\speeduino v29.1\...

The local avr-libstdcpp include flag was unquoted, so the compiler split the
-I path at that space and never searched the actual include directory.

v29.3 changes:
-I${PROJECT_DIR}/.pio/avr-libstdcpp/include
to:
-I"${PROJECT_DIR}/.pio/avr-libstdcpp/include"

Build procedure:
1. Extract v29.3 into a fresh folder.
2. PlatformIO Clean.
3. Build megaatmega2560.

For maximum safety, a folder name without spaces also works, e.g.
C:\Users\leema\Speeduino\speeduino_v29_3\

Firmware signature:
speeduino 202504-flexrot-v29.3
