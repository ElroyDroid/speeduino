Speeduino custom v29.2 - avr-libstdcpp build fix

Functional ECU behaviour is unchanged from v29.

Why v29.1 still failed:
- The v29.1 pre-build script ran before PlatformIO had created/downloaded the
  avr-libstdcpp dependency, so it reported 'patched 0 header(s)'.
- The compiler then built without the expected STL implementation and reported
  std::array, std::lower_bound, std::numeric_limits, etc. as missing.

v29.2 fixes the ordering problem by:
- removing the remote avr-libstdcpp PlatformIO dependency from the Mega2560 env,
- downloading the upstream avr-libstdcpp headers itself during the pre-build step,
- placing them in .pio/avr-libstdcpp,
- compiling with that exact include path.

The upstream project currently documents avr-gcc 7 through 15 as supported,
which includes PlatformIO's avr-gcc 7.3.0.

Build:
1. Extract to a fresh folder.
2. PlatformIO Clean.
3. Build megaatmega2560.
4. Look for:
   "avr-libstdcpp: fetching upstream GCC7-compatible headers..."
   followed by
   "avr-libstdcpp: ready at ..."
